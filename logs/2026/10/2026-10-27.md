# LeetCode 4: Median of Two Sorted Arrays

Problem: https://leetcode.com/problems/median-of-two-sorted-arrays/

## 1. Problem Overview

Given two sorted arrays, `nums1` and `nums2`, return the median of all their elements.

- If the total number of elements is odd, return the middle value.
- If it is even, return the average of the two middle values.
- Duplicate values count as separate elements.

| Arrays | Combined and Sorted | Median |
|---|---|---|
| `[1, 3]`, `[2]` | `[1, 2, 3]` | `2.0` |
| `[1, 2]`, `[3, 4]` | `[1, 2, 3, 4]` | `2.5` |
| `[1, 2]`, `[2, 3]` | `[1, 2, 2, 3]` | `2.0` |

The required time complexity is `O(log(m + n))`.

## 2. My Initial Approach

My plan was to:

1. Find the length of each array and add them together.
2. Determine whether the total length is odd or even.
3. Combine the arrays and sort them in ascending order.
4. Return the middle value or the average of the two middle values.

This approach can calculate the correct median, but it does not meet the required logarithmic time complexity.

I used it to practice Python syntax and understand the calculation before working on a more efficient solution.

## 3. Mistakes and Lessons Learned

### 3.1. Variable Scope and Indentation

**What I expected**

Once I defined a variable, I could use it anywhere below that line.

```python
def example():
    midOrder = 0

print(midOrder)
```

**What actually happened**

`midOrder` was a local variable inside the function, but `print()` was outside it because of its indentation.

```python
def example():
    midOrder = 0
    print(midOrder)
```

**What to remember**

Check where a variable is defined and where it is used. Python uses indentation to determine which block a statement belongs to.

### 3.2. `print()` and `return` Have Different Purposes

**What I expected**

Printing an intermediate value would be enough to run my unfinished solution without a grading error.

**What actually happened**

The function ran, but LeetCode expected a numeric return value. Without an executed `return` statement, the function returned `None`.

```python
print(midOrder)   # Displays the value
return midOrder  # Returns the value and exits the function
```

**What to remember**

Use `print()` to inspect intermediate values and `return` to provide the final answer.

A function can execute without `return`. The error occurs when LeetCode tries to grade the missing numeric result.

### 3.3. `len()` Already Returns an Integer

**What I expected**

I needed to convert array lengths to integers.

```python
m = int(len(nums1))
```

**What actually happened**

`len()` already returns an integer, so the conversion was unnecessary.

```python
m = len(nums1)
```

Also, integer inputs do not guarantee an integer division result:

```python
5 / 2   # 2.5
5 // 2  # 2
```

**What to remember**

`int()` only converts the value it receives. It does not keep future calculation results as integers.

For nonnegative integer lengths, `// 2` produces an integer middle index.

### 3.4. `.sort()` Returns `None`

**What I expected**

This would store the sorted list in `newList`:

```python
newList = mergeList.sort()
```

**What actually happened**

`.sort()` changed `mergeList` directly and returned `None`.

To sort the existing list:

```python
mergeList.sort()
print(mergeList)
```

To create a new sorted list:

```python
newList = sorted(mergeList)
```

**What to remember**

- `list.sort()` modifies the existing list and returns `None`.
- `sorted()` returns a new sorted list.

### 3.5. Check the Total Length Before Dividing

**What I expected**

I could divide the total length first and then check whether it was odd or even.

```python
midOrder = (m + n) / 2

if midOrder % 2 == 0:
    ...

if midOrder % 2 == 1:
    ...
```

**What actually happened**

When the total length was `3`, `midOrder` became `1.5`.

```python
1.5 % 2  # 1.5
```

Neither condition was true, so both branches were skipped.

The parity check should use the original total length:

```python
total = m + n

if total % 2 == 0:
    # Even number of elements
    ...
else:
    # Odd number of elements
    ...
```

**What to remember**

Separate these steps:

1. Determine whether the total length is odd or even.
2. Calculate the middle index or indices.
3. Read the values at those indices.

Avoid dividing an already-halved length again.

### 3.6. Choosing Between `if`, `elif`, and `else`

**My question**

Should every condition after an `if` use `elif`?

**What I learned**

Separate `if` statements are checked independently.

An `if` / `elif` / `else` chain executes only the first matching branch.

Since an integer length must be either odd or even, `if` / `else` is enough for this problem.

**What to remember**

Choose based on whether multiple branches may execute or only one should execute.

### 3.7. `2` and `2.0` Represent the Same Numeric Value

**My question**

Does a floating-point answer mean I need an extra calculation for an odd-length array?

**What I learned**

No. For `[1, 2, 3]`, the median is the middle value, `2`. It can also be represented as `2.0`.

```python
float(2)  # 2.0
```

**What to remember**

The median calculation and the result's data type are separate concerns.

### 3.8. Python Has a Median Function

Python provides `median()` in the `statistics` module:

```python
from statistics import median
```

It belongs to `statistics`, not `math`.

However, it sorts the input internally, so it does not meet this problem's logarithmic time requirement.

**What to remember**

A library function can produce the correct answer without meeting the required efficiency.

The issue is time complexity, not a prohibition on imports.

## 4. Length, Index, and Value Are Different

```python
nums = [10, 20, 30, 40, 50]
```

| Concept | Result | Meaning |
|---|---|---|
| Total length | `5` | Number of elements |
| Middle index | `2` | Position of the middle element |
| Median value | `30` | Value at that position |

Python list indices start at `0`.

For a sorted list with length `total`:

| Case | Middle Index or Indices | Median |
|---|---|---|
| Odd | `total // 2` | Value at that index |
| Even | `total // 2 - 1`, `total // 2` | Average of the two values |

For `[10, 20, 30, 40]`, the middle indices are `1` and `2`.

The median is the average of the values at those positions:

```python
(20 + 30) / 2  # 25.0
```

It is not the average of the indices.
